# PositiveFinger v0.2 — ごほうび中心への変更

2026-10-22 のユーザー方針により、v0.1の「ポイント保留」を更新。

## 実装

- ホーム・ガチャ・ずかん・設定の4タブ。ポップな配色、輪郭線、指をモチーフにしたベクターの相棒6種。
- 対象の確定入力1件につき5 pt、1日100 pt。同一文の正規化ハッシュで当日中の再付与を防止。
- ガチャ25 pt、6種各1/6、重複あり。残高の減算と相棒の保存は共有ファイルの同一ロック・原子的書込み。
- 最初の相棒「もも」は無料。所有する相棒をホームに設定可能。
- 既存ポイント残高を引き継ぐ。過去の検出回数からポイントを捏造しない。
- 入力中のライブ変換は初回移行時にオフ。ユーザーが設定から再有効化可能。
- 一部の否定表現を除外するルールを追加。文脈理解・AI判別ではなく、誤判定は残る。
- フルアクセスとApp Groupの共有が使えない場合、ポイントの付与はできない。

## 将来のクラウドAI（未接続・現在の通信なし）

ユーザーはクラウドAIを希望。実際に有効化するにはサーバー・APIアカウントと費用設定が必要。

推奨構成：任意の同意 → 確定した対象テキスト → HTTPS中継サーバー → AI → 構造化された判定結果。
APIキーはアプリに含めない。サーバーで認証、上限、レート制御、入力長制限、重複制御。
推論を入力UIの同期処理から切り離す。オフ時・通信エラー時の振る舞いを明示。
入力文を端末に永続キューとして保存しない。入力文のサーバーログを残さず、提供者の保持方針も説明する。
ユーザーがオフにしたら保留リクエストを中止。文中の命令に従わず、判定以外の操作をさせない。
否定・引用・皮肉・混合感情の日本語評価データで品質を比較してからポイントに接続する。
現在の同期プロトコルは端末内判定用。クラウド用には別の非同期境界が必要。

## ポイ活との境界

現時点は端末内専用ポイント。購入・換金・ギフト券・他社ポイントへの交換は未実装。
将来金銭的価値を持たせる場合、端末内残高や端末時刻は信頼せず、サーバー側の台帳と不正対策、交換事業者との接続が必要。

## v0.3 交換所・イベント・運営スタジオ

- 交換所：50 ptで称号、100 ptで背景を交換。既存所有と残高を同一ロック内で検証し二重交換を防止。ホーム等に自動反映。
- イベント：「ありがとうの木」の全員参加クエスト企画画面。全体集計サーバーには未接続。架空の進捗や人数は表示しない。
- 端末限定の練習クエスト：参加後のポイント対象5件で25 pt、一度だけ受取可能。参加・進捗・報酬状態を保存。
- 文字の二重表示：カード全体のshadowが文字にも適用されていたため、背景Shapeのみに影を移動。
- 運営スタジオ：`sites/positivefinger-admin`。オーナー非公開の静的管理プロトタイプ。
  お知らせ原稿作成・検索・状態変更、イベント目標・報酬の編集、交換価格の企画値、JSON書出し。
  保存先はそのブラウザのlocalStorage。端末間同期、アプリへの配信、全員の進捗収集は未実装。
  公開サイトのアクセス制限はSitesのオーナー専用アクセスを利用し、独自の偽ログインは設置しない。

次の接続：アプリ会員ID → 管理者権限で原稿公開 → 公開お知らせ取得API →
イベント参加・重複しない貢献イベントの送信 → サーバーで全体集計 → 達成報酬の一意な受取。
運営画面のローカル編集を、そのまま配信実行と見なさないこと。

### ポイント不増加の修正

同じ文への日単位の付与制限を撤去し、永続化した内部クールダウンで判定する方式へ変更。
間隔の変更UI・説明はアプリから削除。古い設定値も内部固定値に移行する。
フルアクセスの変更前に取得したnilの共有コンテナURLを永続的にキャッシュしない。
共有保存失敗時はキーボードに設定確認の案内を出し、保存成功時に解除。
端末での実入力による獲得確認はユーザー確認が必要。

### 開発ビルド専用の隠しメニュー

設定の最下部にあるアプリ名を5回タップすると開く。
100 / 1,000 / 10,000 pt追加、プレイデータリセット（確認あり）。
テスト追加は日次獲得・クエスト進捗を変更しない。残高上限1,000,000 pt。
リセット対象は共有ストアの残高・検出集計・相棒・交換所有・クエスト・重複情報。
フィードバック設定・ライブ変換設定・OS側のキーボード登録は保持。
ストアの世代を更新し、既存のキーボードプロセス内の重複キャッシュも次の確定入力で更新。
UIと変更APIの双方を `#if DEBUG` で囲み、Releaseビルドには含めない。
