# PositiveFinger アプリ仕様書

バージョン0.1（企画・開発用）｜2026年10月22日

このチャットで提示された仕様を、今回の開発の基準として記録する。

## 1. 概要・目的

PositiveFingerは、日常の文字入力を通してポジティブな言葉や考え方に触れる機会を増やすiOSアプリ。前向きな表現を意識するきっかけ、自分の言葉への気づき、負担の少ない継続、入力の利便性とプライバシーの両立を目指す。

| 項目 | 内容 |
| --- | --- |
| 対応OS | iOS 16以降（開発目標） |
| 対応端末 | iPhone |
| 開発言語・環境 | Swift / Xcode |
| UI | SwiftUI / UIKit |
| 構成 | メインアプリ＋Keyboard Extension |
| 段階 | プロトタイプ |

企画コンセプト：「いつもの文字入力から、ちょっと前向きな毎日へ。」

## 2. 背景

SNSやメッセージなどで毎日文字を入力する一方、自分の前向きな行動や気持ちを振り返る機会は限られている。特別な日記を毎日開く行動を追加せず、普段のキーボードから自然に表現に気づける仕組みを提案する。

## 3. システム構成

メインアプリは設定・利用状況・フィードバックの説明を提供する。キーボード拡張は日本語入力、表現検出、フィードバックを提供する。両者は独立した実行領域で動作し、App Groupsで必要な設定・集計情報を共有する。各アプリの対応する入力欄で利用する。

## 4. 機能と優先度

| 機能 | 内容 | 優先度 |
| --- | --- | --- |
| 日本語キーボード | azooKeyのフリック入力、変換候補、削除、切り替えを活用 | 必須 |
| 表現検出 | 登録キーワード・フレーズによる端末内の検出 | 必須 |
| フィードバック | キーボード上の控えめなアニメーション・メッセージ | 必須 |
| 利用状況 | 検出回数、日別の推移 | 高 |
| 個人設定 | フィードバックの有効・無効、表示頻度 | 高 |
| ポイント | 重複防止や無理なポジティブ化を避ける設計を将来検討 | 保留 |
| SNS API連携 | API制限・ユーザー許可に依存する投稿分析 | 将来構想 |

## 5. 入力・検出・表示

- 基本的な日本語入力を維持して独自機能を追加する。
- 利用開始には、iOS設定でユーザーによるキーボードの追加・有効化が必要。
- 初期段階は語句一致方式とし、将来は文脈を考慮する方式を検討する。
- 例：「今日は友達に『ありがとう』って言えた！」から「ありがとう」を表現の候補として検出する。
- 「ありがとうと言えなかった」などの否定文や引用文を誤判定する可能性がある。ユーザーの気持ちを決めつけない表示とする。
- 入力を妨げないことを最優先とし、表示をオフにしたり間隔を変えたりできるようにする。
- 文字の確定を検出契機とし、SNS等の送信完了と混同しない。
- 集計は入力文章ではなく検出回数などを扱う。

## 6. プライバシー・制約

- 入力文を外部送信しない。全文や入力履歴を保存しない。
- 検出は端末内で行い、保存する集計を必要最小限にする。
- パスワード等の機密入力を解析しない。
- iOSのキーボード拡張の制限に従う。利用できない入力欄やアプリでは標準キーボードへ切り替わる。
- SNS API連携は現段階の必須要件に含めない。

## 7. 開発段階

1. 基盤：Xcodeプロジェクト、azooKey導入、ビルド環境の調整。
2. 基本入力：日本語入力、変換、削除、切り替えの検証。
3. 独自機能：検出、フィードバック、集計・設定の共有。
4. 検証・改善：iPhone実機テスト、誤判定対策、操作性、プライバシー確認。

iPhone 8をXcodeの実行先に選べない問題は、アプリ機能とは分けて対応する。

## 8. 効果と今後の検証

すでに行っている文字入力に、前向きな表現へ気づく機会を加える。心理的な効果は現時点で実証されておらず、今後のユーザーテストで検証する。実装状況と未確認項目はREADMEに区別して記載する。
